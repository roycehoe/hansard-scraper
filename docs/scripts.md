The `scripts/` folder holds one-off diagnostic, write, and check scripts outside the main pipeline. Most write scripts are dry runs unless they get `--commit`, and each entry says how its script writes. [CLAUDE.md](../CLAUDE.md) lists the runs that must follow each kind of write.

## Speech rows and report text

- `copy_sitting_lists_to_raw.py`: copies `sitting.sections`, `annexures`, `vernaculars`, and `a2b` into the same columns of `hansardsittingdateresponse` by sitting date, for the sittings stored before the raw columns existed (migration `e5b9c3d7a2f4`). It fills a NULL raw column only, never overwrites. It makes no request to SPRS. It locks the raw table, checks the written count against the plan and re-counts after. A rerun writes nothing. It is a dry run unless `--commit`. Run as a module.
- `fill_sitting_numbers.py`: fills empty `report.sitting_number`, `sitting.session_no`, and `sitting.sitting_no` from the stored header tables. It is a dry run unless `--commit`.
- `apply_report_titles.py`: rewrites stored titles and subtitles that the current title rule would change. It is a dry run unless `--commit`.
- `apply_source_characters.py`: applies `repair_source_characters`, the parser's repair of the characters SPRS sends broken (mojibake, lost closing quotes and the lost characters with one answer, byte-order marks), to stored speech transcripts and labels and report and sitting markdown. It is a dry run unless `--commit`.
- `apply_language_note_close_marks.py`: drops the `_` a language note left open at the start of a stored transcript, as the parser has since `69476f4`, on rows where nothing else differs from a fresh parse. It counts and leaves every other difference. It reruns the column pass for the reports it wrote. It is a dry run unless `--commit`. Run as a module.
- `apply_footnote_markers.py`: writes the footnote markers the parser has set after a unit letter or a possessive since the exponent test took only 2 and 3, to stored report markdown and transcripts where nothing else differs from a fresh parse. It counts and leaves every other difference. It reruns the column pass for the reports it wrote. It is a dry run unless `--commit`. Run as a module.
- `apply_column_numbers.py`: sets `report.column_start` and `column_end` and each speech row's `column_start`, `column_note`, and `column_suggested` from the column markers in the raw HTML, through `populate/column_numbers.py`. `--report-id` limits it to the reports given. It checks the stored counts by Parliament against its plan before it commits. It is a dry run unless `--commit`. Run as a module.
- `apply_coverage_refill.py`: stores the hits SPRS lists that the database lacks and fills reports stored with empty text, with their speech rows. A dry run fetches the text into the plan file, and `--commit` checks the hits are still unstored and the reports still empty, writes the plan's text and checks the speech counts. Run `apply_speaker_links.py` after it.
- `apply_fresh_parse.py`: rewrites the stored speech rows and markdown of every report whose fresh parse differs, except the reports of a `--held` file and the reports that differ in `kind` only. It pairs stored and parsed rows by speaker and text, keeps the ids of paired rows and the stored `kind` of a paired row whose speaker and text are unchanged, numbers every row 1..n and clears the link of a row whose speaker changes. A dry run writes the plan file, and `--commit` locks the planned reports, builds the plan again, refuses unless it equals the reviewed file, checks the written reports equal the parse, links them through stage 8 and reruns the column pass. Run as a module.
- `apply_speaker_links.py`: links the stored speech and attendance rows that stage 8 would link, the credited rows of `data/unlabelled_speech.json` among them. A dry run writes the plan file, and `--commit` locks the planned rows, checks they are still unlinked, builds the plan again and refuses unless it equals the reviewed file.
- `apply_speech_sitting_date.py`: runs migration `c93f77e499cc`, which copies `speech` with each report's sitting date and swaps the copy in, and `alembic check` in one transaction, run as a module. The transaction is rolled back unless `--commit`.
- `apply_speech_report_type.py`: runs migration `82478ba59541`, which copies `speech` with each report's type and swaps the copy in, and `alembic check` in one transaction, run as a module. The transaction is rolled back unless `--commit`.
- `remove_excluded_reports.py`: deletes the stored reports listed in `data/excluded_report_ids.json` and their speech, asker, participant, question state, attached file pointer, division, minutes division, division vote and party count rows, after checking each against its kept copy. The log names the reruns of `apply_minutes_divisions.py` and `apply_division_party_counts.py` that a removed paired division needs. It is a dry run unless `--commit`.

## Attendance, members, and persons

- `scrape_speakers_by_parliament.py`: populates the `Speaker` table from parliament.gov.sg. It is a dry run unless `--commit`.
- `load_colonial_la_speakers.py`: loads, idempotently, `data/colonial_la_members.json` and `data/unscraped_members.json` into the `Speaker` table. Must be run before `populate_speaker_links`. It is a dry run unless `--commit`.
- `load_heads_of_state.py`: loads, idempotently, `data/heads_of_state.json` (Governors, the Yang di-Pertuan Negara, Presidents) into the `Speaker` table as non-member rows. Run after `load_colonial_la_speakers.py` and before `populate_speaker_links`. It is a dry run unless `--commit`.
- `load_parliament_speakers.py`: stores the members of one Parliament (`--parliament N`) that the `Speaker` table lacks, from parliament.gov.sg, with the overrides of `data/speaker_overrides.json`. It is a dry run unless `--commit`.
- `apply_speaker_overrides.py`: applies `data/speaker_overrides.json` and the party values of `data/colonial_la_members.json` to stored speaker rows, and straightens the apostrophe in party. It is a dry run unless `--commit`.
- `apply_speaker_parliaments.py`: moves the stored Assembly-only speaker rows to the Parliament that `data/colonial_la_members.json` and `data/heads_of_state.json` give them. It is a dry run unless `--commit`.
- `complete_truncated_attendance.py`: inserts the attendance rows stage 7 builds from a sitting's markdown that its stored rows lack, linked as stage 8 links them, in sittings that already hold rows (stage 7 fills a sitting with none). It refuses the whole run when a short sitting holds a stored row stage 7 does not build. A dry run writes the plan file, and `--commit` builds the plan again, refuses unless it equals the reviewed file, and checks each sitting's count before it commits.
- `apply_attendance_names.py`: sets stored attendance names to the names stage 7 builds, on rows where nothing else differs. It pairs the rows equal in name, presence, and location first and the rest by position, and refuses a sitting whose rows differ in more than a name. It is a dry run unless `--commit`.
- `apply_constituency_names.py`: rewrites stored attendance location names that `data/constituency_names.json` would change. It is a dry run unless `--commit`.
- `clean_attendance.py`: deletes the attendance rows of `data/attendance_cleanup.json` that the stage 7 parser no longer builds, renames and links its corrections, and links each `Speaker` role row to the presiding officer of its date or deletes it when he has another row. It is a dry run unless `--commit`.
- `load_party_affiliations.py`: loads, idempotently, `data/party_affiliations.json` into the `PartyAffiliation` table, run as a module. It skips rows already stored and refuses when a stored row for the same speaker differs from the file. It is a dry run unless `--commit`. The party on a vote row is fixed when the row is written and the daily role cannot update it, so after a load that changes a Member's spans, rerun `python -m scripts.apply_minutes_divisions --plan-file ... --commit --minutes-id ...` for the sittings of that Member's votes and `python -m scripts.apply_divisions --plan-file ... --commit --report-id ...` for the reports of the Hansard lists they sat in (both write vote rows with the party fixed at write time), and then `python -m scripts.apply_division_party_counts --plan-file ... --commit --division-id ...` for their divisions, because the breakdown counts the party fixed on the vote row.

- `apply_report_put_to.py`: stores the office each parliamentary question report (oral-answer, written-answer, written-answer-na) was put to in `report_put_to`, through `populate/report_put_to.py`, read from the question row's "asked the" or "To ask the". It is a dry run unless `--commit`. Run as a module.
- `apply_attendance_offices.py`: stores the printed office of each attendance entry in `attendance_office` through `populate/attendance_offices.py`, then deletes every `office_printed_range` row and builds the ranges again from the stored offices. `--sitting-id` limits the office rows, never the ranges. It checks the stored counts by decade against its plan before it commits. It is a dry run unless `--commit`. Run as a module.
- `apply_ministries.py`: stores the names of `data/ministry_names.json` in `ministry` and places every printed office title of `attendance_office`, `report_put_to` and `report_participant` under its ministries in `office_title_ministry`, through `populate/office_title_ministries.py`. A name kept in the file keeps its `ministry.id`. It logs the titles it cannot place. It checks the stored names and placements against its plan before it commits. It is a dry run unless `--commit`. Run as a module.

A rerun skips the files it holds. The eGazette terms (clause 11) require the attribution lines of `docs/report/bill-linking-build-2026-11-08.md` wherever the PDFs' content is reproduced.

A row seen in two captures is stored once. The dry run writes the plan file (`--plan-file`) and logs the capture, entry, and duplicate counts, and `--commit` refuses unless the plan equals the reviewed file and checks the stored counts. Run as a module.
- `apply_acts_supplement.py`: stores the Acts Supplement listing captures of a directory (`--captures-directory`: `captures.json` and one HTML file per capture) in `actssupplementcapture` and their rows in `actssupplemententry`, through `populate/acts_supplements.py`. A row seen in two captures is stored once. The dry run writes the plan file (`--plan-file`) and logs the capture, entry, and duplicate counts, and `--commit` refuses unless the plan equals the reviewed file and checks the stored counts. Run as a module.
- `apply_repealed_acts.py`: stores the Singapore Statutes Online (SSO) Repealed Acts listing captures of a directory (`--captures-directory`: `captures.json` and one HTML file per capture) in `repealedactscapture` and their rows in `repealedactentry`, through `populate/repealed_acts.py`. An Act seen in two captures is stored once, from the first. The dry run writes the plan file (`--plan-file`) and logs the capture, entry, and duplicate counts and the entries by decade of enactment year, and `--commit` refuses unless the plan equals the reviewed file and checks the stored counts. Run as a module.
- `apply_egazette_supplements.py`: stores one `egazettesupplement` row per PDF of a fetch directory (`--harvest-directory`: the `fetches.json` and PDFs of `fetch_egazette_supplements.py`) with the fields read from its text through `populate/egazette_supplements.py`, inserting new rows and updating changed ones by URL. The dry run writes the plan file (`--plan-file`) and logs the PDFs it could not read, and `--commit` refuses unless the plan equals the reviewed file and checks the stored rows. Run as a module.
- `apply_act_links.py`: stores the bills grouped from the `bill` and `bill-intro` reports and the other-type reports whose title ends in Bill and which hold a reading line (a report whose printed title misspells its bill is grouped under the corrected title of `data/bill_title_corrections.json`, and the bills of `data/hand_kept_bills.json` are built from their listed reports, a motion's among them; the eleven entries of `data/hand_kept_act_links.json` link to the bill holding exactly their listed reports before any rule is tried), the Acts of a harvest directory (`--harvest-directory`: `acts.json` and one `pdftotext -layout` text file per Act, named `<sso_code>.txt`), their Legislative History entries and the link from each Act or Ordinance entry to a bill, through `populate/act_links.py`. The link takes the bill whose title key matches the entry's title and which has a report within a day of the entry's first, then third, then second reading date, failing that the one bill whose looser key (amendment and number words removed) has reports within a day of the first and third reading dates. The dry run logs the counts (bills, Acts, entries by kind, links by rule, unlinked entries by kind and decade, source defects, unparsed entries) and writes the plan file (`--plan-file`). The dry run also logs what the write would change against the stored rows (bills kept, updated, inserted and deleted; Acts and entries inserted, updated and deleted; linked entries that change bill). `--commit` refuses unless the plan equals the reviewed file, then applies it to the four tables (a bill is keyed by its report ids, an Act by `sso_code`, an entry by its Act's `sso_code` and `ordinal`; unchanged rows keep their ids) and checks the stored counts and rows against the plan before it commits, so a second run of the same plan writes nothing. Run as a module. The plan also carries each bill's number, source and class, the split merges, the eGazette Acts links, and for each Act or Ordinance entry the bill its printed bill number names when that bill has a report within a day of the entry's first reading (`bill_number_bill_index`). The plan also carries each passed bill's Act number from the Acts Supplement entries (`act_number`, `act_number_source`), logged by source with the count of passed bills without one, and the commit checks the stored count of bills with an Act number. The plan also carries each passed bill's repealed Act page (`repealed_act_url`, `repealed_act_url_source`), logged by source with the count of passed bills without one, and the commit checks the stored count of bills with one. The plan also attaches each `budget` report to a Supply Bill as a BUDGET_DEBATE `billreport` row (`budget_report_links`, `budget_report_count`), through `get_supply_bill_indexes_for_budget_report`: a main budget report (its title has no "supplementary", "excess" or "final") takes the main Supply Bill (title key `supply` or `appropriation` with year and number parts, then `bill`), and any other budget report takes a Supplementary, Final or Excess Supply Bill, whose window holds the report's date from 45 days before the bill's first report to 30 days after its last. A report with exactly one such bill is linked, one with two or none is not, and a report already grouped as a reading is left out. The dry run logs the linked count of the budget reports, the write logs the budget links inserted and deleted, and the commit checks the stored READING rows against the planned reports and the stored BUDGET_DEBATE rows against the planned links. Run it after `apply_bills_supplement.py`, `apply_egazette_supplements.py`, `apply_acts_supplement.py` and `apply_repealed_acts.py`, which it reads.
- `apply_hand_kept_act_links.py`: labels the Legislative History entries of `data/hand_kept_act_links.json` HAND_KEPT without the SSO harvest, after checking each entry's stored printed title and that its bill holds exactly the listed reports. It is a dry run unless `--commit`. Run as a module.
- `apply_bill_speakers.py`: stores `billkey`, `billreportspeaker`, and `billstageline` through `populate/bill_speakers.py`: each bill's key report and Act count, one row per Member and report, and one row per printed first reading, order for second reading, accordingly-read second reading and third reading line of kind `PROCEDURAL` or `UNCLASSIFIED`. `--report-id` (the integer `report.id`) limits it to the reports given and leaves other reports' rows alone, and a report no bill holds loses its stale rows. The dry run logs, per table, the rows to add, remove and change. It checks the stored counts by decade and report type and by stage against its plan, and each key against the bill's first READING report, before it commits. It is a dry run unless `--commit`.
- `list_bill_review_items.py`: runs read only. It writes the review list of objective 7 (`--review-file`, JSON parsed by `schemas/bill_review_list.py`) and its summary lines (`--summary-file`, kept in `docs/figures/`): Supplement entries placed only by a loose or similar title, entries with two same-title bills in their window, unplaced entries with the bill the neighbouring numbers' first readings propose, misprinted publication dates, split-bill merges (marked when they equal a hand-kept bill), Legislative History entries whose printed bill number names a bill the title rules do not link or a different one, linked entries whose bill has no report within a day of the third reading, passed bills from 1966 with no Supplement entry, passed bills with two Act numbers of their title in the Acts Supplement window, and Acts Supplement entries whose Act number no passed bill takes (with the nearest passed bill of the title), and passed bills whose dates fit two repealed Acts of their title (`REPEALED_ACT_BILL_WITH_TWO_ACTS`). - `replay_bill_placement.py`: runs read only. Run as a module.

## Attached files

- `apply_attached_files.py`: stores the files each sitting lists and the pointers in each report's raw HTML, and ties them, through `populate/attached_files.py`. With no `--report-id` it plans every sitting and every report with a download link, and with `--report-id` only those reports and no file rows. It logs the files by kind, the pointers by shape, the paragraph ties by tier, the pointers that would take a file and the stale paragraph ties. `--commit` replaces the pointers of each report whose stored rows differ from the plan, sets the file ties, checks the stored rows against the plan and vacuums the two tables. It is a dry run unless `--commit`. Run as a module.
- `check_attached_file_addresses.py`: reads the stored addresses and asks SPRS about a sample of them, one request at a time through `gateway/sprs_file.py`: a known-good address and four made-up ones first, stopping when SPRS answers a made-up address as it answers the real one, then 50 addresses per group, every non-ASCII address, the two with a trailing space and the placeholder. It writes one result per address (`ANSWERED`, `UNPROVEN` or `FAILED`) and stores nothing. Run as a module.
- `collect_attached_file_flags.py`: runs read only. Merges the flag files of every round and the address results into one file, keeping one entry per pointer with its rounds and whether the stored tie still equals the flagged one, and the unproven and failed addresses. A flag stays until the maintainers clear it. It refuses an existing output. Run as a module.

## Accuracy checks: draws, packets, and flag lists

- `draw_office_check_sample.py`: runs read only. It draws a seeded sample of at most 50 rows per group of one rule (`attendance-office`, `put-to` or `ministry`), with 15 planted errors, and writes `records.json`, `reader-packets.md` (no row key, source or group), a sealed `plant-key.json` with its SHA-256 and `summary.txt` to a directory that does not exist yet. Run as a module.
- `list_office_check_flags.py`: needs no database. It refuses unless each packet has exactly one valid verdict from the Sonnet and the Opus reader and the plant key matches its committed hash. It flags a sampled row when either reader's verdict is not `RIGHT`, scores each reader against the plants and never lists a plant as a flag. It refuses to overwrite its output. Run as a module.
- `build_report_link_check.py`: runs read only. It draws the report link accuracy check from the stored links, after refusing unless the stored keys equal the plan's. Stage 1 samples up to 50 links from each of five groups (correction, reply, continuation with one title, last part in the newer system, last part in the older system) and `--rule` draws stage 2 for one looser rule, grouped by decade and report type. It plants 5 wrong links per group (or per rule), writes `records/packets.json`, `records/draw-summary.txt`, the sealed `key/plant-key.json` with its SHA-256, and shuffled `batches/sonnet` and `batches/opus` trees of `packets.md` that show a random packet id and never a report id, rule or group. The output directory must not exist yet. Run as a module. The readers' rules are `docs/report/report-links-check.md`.

Run as a module.
