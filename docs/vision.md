# Vision

A complete, queryable record of Singapore's parliamentary proceedings — from the colonial Legislative Assembly through the present — for researchers studying political history at scale. The site built on it, openhansard.sg, is for people who read Hansard: someone who wants to find what an MP said and send it on, look up their own MP, quote a paragraph in an article, or question the name above it (hansard `docs/user-testing.md`).

The at-scale part of that goal needs the database published, and Parliament's terms of use require written permission to reproduce the content. The project will not ask for it. On 2 November 2026 Royce ruled to wait for a takedown request instead, and to act on one if Parliament sends it. The site's `docs/corrections.md` and `docs/takedown.md` promise to take a report off the site within 2 working days of such a request. The database stays unpublished, so this file counts the bulk-researcher goal as not met, and the done tests below leave it out.

## Objectives

### 1. Complete corpus coverage
Fetch and store every Hansard entry published by SPRS, across all parliaments and all report types. No gaps from rate limits, format changes, or API quirks. The raw API response for every record is preserved exactly as received.

### 2. Per-utterance speaker index
Extract individual speeches from parliamentary transcripts and attribute each one to the correct speaker. Each `Speech` row represents one utterance — a single content line in the debate — with an `ordinal` that preserves delivery order within the report. The speech table is a queryable, speaker-filtered index over the report content: a researcher can retrieve all speeches by a given speaker across the corpus, sorted by ordinal to read them in context. The `markdown_content` on `Report` is the source of truth; speeches are a derived index over it, not a line-for-line mirror.

Attribution should be as complete as the source material allows. Documents that remain unattributed must be structurally unattributable (appendix link indexes, colonial-era procedural orders with no named author). Structural limits that apply by design:
- `Speech.speaker` may be `None` for utterances where no speaker attribution is possible. Speakers are not guaranteed. A row's `kind` says what a row with no speaker is ([ADR 0009](adr/0009-speech-kind-column.md)). The parser sets it on every row since `0969500`, and write #3 stored it on 16 October 2026 for every report it rebuilt.
- Single-speaker documents are stored as one `Speech` row for the speaker's text rather than per-line rows. The report title is dropped from it, and procedural lines and a first reading become rows of their own with no speaker.
- Documents with multiple speakers but no bold speaker markup produce zero `Speech` rows.
- The report's own title line, the report header fields and blank lines get no `Speech` row. The parser has kept text before the first speaker as rows with no speaker since `e890946` ([ADR 0008](adr/0008-text-before-the-first-speaker-kept.md)); write #3 stored it on 16 October 2026 for every report it rebuilt.

### 3. Rich sitting metadata
For every sitting date, capture full session metadata: attendance, permissions to be absent, debate sections, vernacular speeches, and annexures. Both pre- and post-August 2015 API formats are handled faithfully.

### 4. Speaker identity linking
Connect every speech and attendance record to a canonical speaker identity (name, party, parliament number) sourced from parliament.gov.sg.

### 5. High-fidelity markdown
Convert raw HTML records into clean, readable markdown that downstream consumers can trust — stripping artifacts introduced by html2text across three distinct document eras (colonial, mid-era, modern) without losing any substantive content.

### 6. Parsing quality
Track parsing success rates per report type across the full corpus so regressions surface before they accumulate and improvement work is measurable.

## Strategies

### Raw first, derive second
Every external API response is stored in a raw response table before any transformation occurs. Entity tables (Report, Sitting) keep every field of their raw counterparts, and the values they change are listed in [data-loss-register.md](data-loss-register.md): cleaned titles, sitting and session numbers filled from the header table, and empty strings stored as NULL. The source of truth is always recoverable. Re-parsing is not cheap, though. A stage skips rows that already exist, and dropping speech rows would lose their ids and links, so stored reports are rebuilt through planned, rehearsed writes.

### Staged, incremental population
The pipeline runs in discrete stages, listed in `CLAUDE.md`. `script.py` runs stages 5 to 9, the sitting, attendance, linking and person stages. Stages 1 to 4 (search, report fetch, reports, speeches) have no entry point there and run from the fill and rebuild tools. Each stage skips what is already stored, so a run resumes after an interruption. The same skip means a parser change never reaches stored rows on a rerun.

### One request at a time, with backoff on 429
The gateway layer sends one request at a time and waits at least 2 seconds between requests, retries included. Its user agent names the project. On HTTP 429 it backs off exponentially with jitter, so the pipeline slows down under load instead of failing or hammering the server.

### Iterative parsing refinement
Parsing improvements follow a structured loop: inspect failure categories, apply a targeted fix, add a golden fixture, measure the attribution figures before and after, and commit to master. The speech fidelity loop ([speech-fidelity-loop.md](report/speech-fidelity-loop.md)) adds hand reads against the source and a stopping rule. The corpus holds 41,801 reports.

### Format-aware artifact removal
The raw HTML comes from two systems: the older one (sprs2, sittings before 10 September 2012) and the newer one (sprs3). `utils/markdown_parser.py` and `services/speech.py` branch on `report_version` where the two differ. Most cleaning steps, such as turning `&nbsp;` into a space and merging bold lines split across page breaks, run on every report. A step that applies to one system only is guarded by `report_version`, so the other system's output does not change.

### Principled attribution hierarchy
Bold speaker labels come first. For a report with none, attribution follows a fallback chain in `services/speech.py`:
1. If the `MPs Speaking` header lists exactly one name, the body goes to that speaker as one row.
2. Otherwise the report type decides: the speaker line of an atbp report, the minister of a President's Address addendum (or the President when no ministry heading appears), the mover of an adjournment motion, and the presenter of a bill or, in the newer system, a bill introduction.
3. If neither applies, the report stays unattributed. Multi-speaker appendix documents and authorless procedural orders get no invented speaker.

The atbp credit is deliberate, although nobody speaks a notice of assent. The Speaker writes and signs it, so its words are his, and it stands in for an announcement he would otherwise make in the House. Royce ruled to keep it on 1 Nov 2026, after the accuracy sample counted one as an error.

### Diagnostic tooling as a first-class concern
Targeted validation and inspection tools live alongside the main pipeline. Nothing exports statistics automatically. `scripts/attribution_text_share.py` prints the attribution figures by Parliament group and by report type when it is run, with the zero-row reports and single-speaker collapses, and `--output` keeps a copy in a file. `CLAUDE.md` asks for it before and after every parsing or linking change. These tools make it possible to audit specific failure categories without re-running the full pipeline.

### What "parsed" means in each check

None of the automated checks tests that text sits under the right speaker. Read each pass as the narrow claim it is.

| Check | Passes when | Misses |
|---|---|---|
| `scripts/diagnose.py` | A title line is found | Zero or wrong speeches; it discards the `get_speeches` output |
| `scripts/run_sanity_check.py` | Title found, at least one speech, no NULL speaker, on a fixed sample | Wrong speaker or lost text; it rewards crediting procedural lines to the last speaker |
| `scripts/run_no_speech_validation.py`, `scripts/run_exclusion_sanity_check.py` | A zero-row report has no bold speaker markup | Speeches without bold labels |
| `scripts/trace_speaker_links.py` | Stored links equal what the resolver returns today | Whether the resolver is right; role-context rows are not re-evaluated |
| `scripts/check_link_plausibility.py` | It always passes; it lists linked rows whose person was absent or unlisted that sitting, unlinked speaker strings outside the known-unlinkable classes, and sittings with a short attendance list | Wrong links to someone who was present; it cannot tell a wrong link from a wrong attendance row. On 14 October it flagged 378 (report, person) pairs, and a 30-pair sample was 24 attendance errors, 0 link errors |

### Where more work stops paying

Published peers report less than this project. The Knesset corpus reports 94.5% of speaker strings matched to its member database, and 98.3% speaker-name correctness on a hand-checked test set; a 2026 paper linking the UK Hansard corpus to MPs reports 89.3% for the Commons; ParlaMint, the Australian Hansard datasets and TheyWorkForYou publish no linking rate. None found resolves an unnamed presiding officer to a person: ParlaMint tags the role, the Knesset corpus flags the chair, and Spain's ParlaMint corpus leaves them blank. So work on unnamed chairs, or resolver tuning that moves the rate by tenths of a point, is past the point of value. Work that moves text share, coverage or measured precision is not.
