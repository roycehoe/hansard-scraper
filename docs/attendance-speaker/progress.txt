## Iteration 1

### can_match — all buckets — apply resolve_canonical_name + parl-0 fallback

**Affected IDs (pilot):** all 30 (mid: 74446, 77476, 67150, 40062, 18846, 1035, 31918, 21637,
  29387, 22408; modern: 51869, 56578, 30460, 73692, 22984, 31004, 43879, 11877, 46223, 3745;
  colonial parl=0 fixable: 25010; colonial parl=1 fixable: 61812)
**mp_name (failing):** "Abdullah Tarmugi" (parl=6,8), "Tony Tan Keng Yam" (parl=7),
  "Sidek bin Saniff" (parl=8), "S. Jayakumar" (parl=9), "George Yong-Boon Yeo" (parl=9)
**mp_name (passing, regression):** Already matched rows all used exact dict lookup at ingestion
**Expected Mp.name:** "Abdullah Bin Tarmugi", "Tan Keng Yam, Tony", "Sidek Bin Saniff", etc.
**Root cause:** `_populate_attendance_mp_ids` does raw exact `mp_id_lookup.get((record.mp_name, parliament))`
  with no title-stripping, normalisation, or cascade. The speech pipeline applies the full cascade;
  the attendance pipeline does not.
**Proposed fix:** In `_populate_attendance_mp_ids`, after the raw lookup fails, apply:
  1. `strip_title(record.mp_name)` → `normalize_name()` → `resolve_canonical_name(name, parliament)`
  2. If still None and parliament == 0: try fallback parliaments 1, 2, 3
  3. Use canonical to look up mp_id
**Backward-compatibility:** Raw exact lookup still runs first (handles already-canonical names
  without extra work). The cascade only runs on non-matches, so no regression risk.
**Outcome:** KEPT

| Set | Before | After |
|---|---|---|
| Pilot | 0/30 | 22/30 |
| Held-out | 0/15 | 13/15 |
| Regression | 30/30 | 30/30 |

## Production verification — 2026-06-05

The 91.2% figure above reflected an intermediate state of the dev corpus (older ingestion
pass with non-canonical speaker_name values). Full production run tells a different story.

### What changed

Stage 7 (populate_attendances) had only processed 191/1,719 sittings in production.
The remaining 1,528 sittings (all with PRESENT sections in markdown_content) were
populated on 2026-06-05, bringing the attendance table from 14,000 → 96,500 rows.

Stage 8 (populate_speaker_links) then resolved speaker_ids on the 82,525 new rows.

### Production result

| Metric | Value |
|---|---|
| Total attendance rows | 96,500 |
| Matched (speaker_id non-null) | 96,298 |
| Unmatched | 202 |
| Match rate | **99.8%** |

All 202 unmatched rows are in the parl=0 (colonial) bucket — structurally absent names
with no Speaker row reachable via the parliament fallback chain [1, 2, 3].

### Why 99.8% vs the earlier 91.2%

The current get_sitting_attendance already canonicalises speaker_name at ingest time via
resolve_canonical_name. By the time populate_speaker_links runs, most speaker_name values
are already in canonical form and get an exact dict hit. The 91.2% figure was from a
corpus where rows had been ingested without that canonicalisation step.

### Remaining ceiling

The 202 unmatched rows are the true production floor. They are all colonial parl=0
sittings where the name has no Speaker row at parliament 1, 2, or 3. Resolvable only
by adding confirmed LA members to data/colonial_la_members.json (see research-loop.md).
