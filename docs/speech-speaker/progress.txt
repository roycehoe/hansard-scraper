### can_match — all types — date-based Chief Minister dispatch + denominator measurement fix

**Affected Speech IDs (pilot):** 6x `The Chief Minister` (parl=0): IDs 310147, 328557, 331314, 331410, 334635, 335143

**Speaker string (passing, same report_type):**

**Proposed fix:**
1. Added `Report.sitting_date` to `get_speaker_info_by_ids` query in `crud/speech.py` (4-tuple return).

The pilot script was counting `_preprocess`-returning-None speeches (structural exclusions: `_NON_SPEAKERS`, `startswith("(")`, `startswith("_")`) in the denominator as failures. ## Iteration 20 — 2026-06-01

### can_match — all types — role-only ministerial strings resolved by parliament→person mapping

**Affected Speech IDs (pilot):** 13x `The Prime Minister` (various parliaments), 1x `The Minister for Health` (parl=11) — 14 total unmatched in prior iteration.

**Speaker string (failing):**
`The Prime Minister` (×13 in pilot, spanning parl=0–11) — role-only string, no individual name present; the existing name cascade produces no match because there is nothing to resolve as a name.
`The Minister for Health` (×1, parl=11) — same pattern.

**Speaker string (passing, same report_type):**
`The Prime Minister (Mr Goh Chok Tong)` — role+name parenthetical; inner name extracted and resolved by the existing paren-extraction logic (iteration 2/18). The failing cases are the raw role string with no parenthetical at all.

**Expected Speaker.name:**
- parl=0–3,5–6: `Lee Kuan Yew` (LA era and early parliaments)
- parl=8: `Goh Chok Tong`
- parl=11: `Lee Hsien Loong`
- `The Minister for Health`, parl=11: `Khaw Boon Wan`

**Root cause:**
Role-only strings carry no individual name. The entire resolution cascade (strip_title → normalize → resolve_canonical_name) operates on name tokens and produces no match for a string like `The Prime Minister`. There is no pre-processing step that can extract a name that isn't present.

**Proposed fix:**
Added `_ROLE_ONLY_SPEAKERS: dict[tuple[str, int], str]` with 9 entries mapping `(role_string, parliament_number)` → canonical name. Added early handler in `_populate_speech_speaker_ids` immediately after the presiding-officer block: if `raw` is a key in `_ROLE_ONLY_SPEAKERS` (with colonial parliament fallback for parl=0), resolve the mapped person name via `_resolve_with_parliament_fallback` and set `speaker_id`. `continue` fires unconditionally — role-only strings are never resolvable via the name cascade. Updated `scripts/run_pilot_assessment.py` and `scripts/run_regression_check.py` to mirror the new logic.

**Dict built:**
```python
_ROLE_ONLY_SPEAKERS: dict[tuple[str, int], str] = {

    ("The Prime Minister", 1): "Lee Kuan Yew",   # Parliament 1 (1959–63)
    ("The Prime Minister", 2): "Lee Kuan Yew",   # Parliament 2 (1963–68)
    ("The Prime Minister", 3): "Lee Kuan Yew",   # Parliament 3 (1968–72)
```

### can_match — all types — loop strip_title until stable for stacked titles

**Affected Speech IDs (pilot):** None in current pilot — `Assoc. Prof. Dr Yaacob Ibrahim` and `RAdm [NS] Lui Tuck Yew` do not appear in the 267-speech pilot set.

**Speaker string (failing):**
`Assoc. Prof. Dr Yaacob Ibrahim` — with single-pass strip_title, only `Assoc. Prof. ` is removed, leaving `Dr Yaacob Ibrahim`; second prefix `Dr ` is never stripped. Similarly `RAdm [NS] Lui Tuck Yew` leaves `[NS] Lui Tuck Yew` after one pass.

**Speaker string (passing, same report_type):**
`Dr Yaacob Ibrahim` — single prefix, already handled in one pass.

**Expected Speaker.name:**
`Yaacob Ibrahim` (parliament 10/11), `Lui Tuck Yew` (parliament 12), etc.

**Root cause:**
`strip_title` returned after the first matching prefix instead of continuing to check whether the remaining string also starts with a title prefix. Stacked titles like `Assoc. Prof. Dr` require two stripping passes.

**Proposed fix:**
Replace single-pass loop with a `while True` outer loop that re-scans `_TITLE_PREFIXES` after each prefix is stripped; exit via `for`/`else` when no prefix matches (string is stable). This is a pure superset of the prior behaviour.

**Note:** The loop version was already present in `services/attendance.py` (committed in earlier iterations). The proposed change is a no-op — `git diff HEAD services/attendance.py` shows no difference. The pilot sample does not contain any stacked-title failure cases, so the metric is unchanged.

**Backward-compatibility:**
Strings with a single title prefix behave identically — the inner `for` loop breaks on first match, the outer `while` re-scans, finds no second prefix, and returns via `else`. No regression risk.

**Outcome:** REVERTED (no change — code already in desired state; pilot count did not increase)

## Iteration 18 — 2026-06-01

### can_match — all types — double-parenthetical extraction (scan all parens right-to-left for title-bearing group)

**Affected Speech IDs (pilot):** 193673 (`The Second Deputy Prime Minister (Foreign Affairs) (Mr. S. Rajaratnam)`) and similar double-paren minister strings

**Speaker string (failing):**
`The Second Deputy Prime Minister (Foreign Affairs) (Mr. S. Rajaratnam)` — two paren groups; old regex matched only the trailing `(Foreign Affairs)` which has no title prefix, so the name-bearing `(Mr. S. Rajaratnam)` was never extracted.
Also newly resolved: `The Deputy Prime Minister (Dr Toh Chin Chye) (Rochore)` and `The Parliamentary Secretary to the Prime Minister (Inche Yaacob bin Mohamed Al-Haj) (for the Prime Minister)` pattern variants.

**Speaker string (passing, same report_type):**
`The Minister for Foreign Affairs (Mr S. Rajaratnam)` — single paren with title prefix; already handled by old logic.

**Expected Speaker.name:**
`Rajaratnam, S` (parliament 5), `Toh Chin Chye` (parliamentary), etc.

**Root cause:**
Old regex `re.search(r"\s*\(([^)]+)\)\s*$", raw)` only looked at the final paren group. For `Role (descriptor) (Mr Name)` the final group is `(Mr Name)` which does contain a title — but for `Role (Mr Name) (locality)` the final group is `(locality)` with no title, and the name-bearing paren is skipped. The fix needs to scan all parens and pick the first one (right-to-left) whose inner text has a recognisable title prefix.

An additional wrinkle: `Mr.` (with period) is not recognised by `strip_title` (which only handles `Mr ` without period). The `_has_title` helper normalises `Mr.` → `Mr` before calling `strip_title` so `Mr. S. Rajaratnam` is correctly identified as title-bearing.

**Proposed fix:**
Replace single-paren regex with `re.finditer` scanning all paren groups. Added `_has_title(m)` helper that normalises `Mr./Mrs./Dr./Ms.` period forms before calling `strip_title`. Scan reversed; take first title-bearing group; if none, strip from first paren onward (unchanged constituency-strip behaviour). Updated `_preprocess` in both `scripts/run_pilot_assessment.py` and `scripts/run_regression_check.py` to mirror the new logic.

**Backward-compatibility:**
Single-paren strings whose inner text has a title prefix are handled identically — `reversed([one_match])` returns that same match and `_has_title` fires the same way. Single-paren strings with no title prefix fall through to `raw = raw[: parens[0].start()].strip()` — same constituency-strip as before. The regression set confirms: 53/53 = 100%.

**Outcome:** KEPT

### can_match — all types — constituency suffix in speaker string

**Affected Speech IDs (pilot):** ~39 (constituency-suffix pattern)

**Speaker string (failing):**
`Dr Tan Cheng Bock (Ayer Rajah)`, `Mr J. F. Conceicao (Katong)`, `Dr Dixie Tan (Ulu Pandan)`,
`Mr Teo Ser Luck (for the Minister for Community Development, Youth and Sports)`,
`Inche Sha'ari Bin Tadin (for the Minister for Culture)`

**Speaker string (passing, same report_type):**
`Mr Christopher de Souza`, `Mr Khaw Boon Wan`, `Dr Goh Keng Swee`

**Expected Mp.name:**
`Tan Cheng Bock`, `J.F. Conceicao` (inverted), `Dixie Tan` (or `Tan Dixie`), etc.

**Root cause:**
`_populate_speech_mp_ids` passes the raw `Speech.speaker` string (after rstrip(':')) directly
to `strip_title` and then `resolve_canonical_name`. When the speaker string carries a trailing
constituency or role parenthetical (`(Ayer Rajah)`, `(Nominated Member)`, `(for the Minister...)`),
the cascade cannot match the name because the lookup keys don't include the parenthetical.

**Proposed fix:**
Pre-processing step before `strip_title`: strip the trailing parenthetical from the raw speaker
string UNLESS its content starts with a title prefix (`Mr`, `Mrs`, `Dr`, etc.), which signals
a role+name pattern (`The Minister (Mr Name)`) that should be handled separately.

**Backward-compatibility:**
All 24 currently-passing pilot speeches have plain names with no parenthetical — the strip is
a no-op for them. Confirmed by simulation: 0 regressions in pilot + regression set.

**Outcome:** KEPT
- Pilot: 24/160 → 50/160 (15.0% → 31.2%), +26 newly matched
- Held-out: 22/93 → 34/93, +12 flipped
- Regression: 30/30 → 30/30, 0 new failures
