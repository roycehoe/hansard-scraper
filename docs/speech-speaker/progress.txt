## Iteration 16 — 2026-06-01

### can_match — all types — strip single-char initials from wordset subset key and query

**Affected Speech IDs (pilot):** Target: speeches with `Dr Aline Wong`, `Dr Augustine Tan`

**Speaker string (failing):**
`Dr Aline Wong` → after strip_title → `Aline Wong` (2 words); canonical `Wong Aline K` has initial `K`. Iteration 15 keyed on `{aline, wong, k}` (build) vs `{aline, wong}` (lookup) — no match.
`Dr Augustine Tan` → `Augustine Tan` (2 words); canonical `Tan H.H. Augustine` → after period-normalise → `{tan, h, h, augustine}` (build) vs `{augustine, tan}` (lookup).

**Speaker string (passing, same report_type):**
Speakers whose canonical name has no single-char initials — unaffected by this change.

**Root cause:**
`_build_wordset_subset_lookup` builds keys from `frozenset(all_words)` including single-char initials. The query side also uses all words. Single-char initials cause the frozensets to differ when the speech string omits the initial.

**Proposed fix:**
Strip tokens of length ≤ 1 from both the build key and the lookup query: `[w for w in words if len(w) > 1]`. Applied to both `_build_wordset_subset_lookup` (build side) and the `_wss_words` lookup in `_try_name_variant`.

**Root cause of failure (actual):**
After stripping the single-char initial `K`, `Wong Aline K` filters down to 2 words (`['wong', 'aline']`). The `_MIN_WORDSET_SUBSET_WORDS = 3` minimum is checked on the *filtered* list — 2 < 3 → the entry is never emitted at build time. The build and lookup keys would match if the entry were emitted, but the guard prevents it. The fix is incomplete without also lowering the minimum to 2 (on the filtered list) or checking the minimum on the pre-filter list.

**Files changed:** `services/attendance.py` (reverted)

**Backward-compatibility:**
N/A — reverted.

**Outcome:** REVERTED
- Regression: 53/53 = 100.0% (no new failures)
- Pilot: 226/267 = 84.6% (no change — same as iteration 15; `Dr Aline Wong` and `Dr Augustine Tan` still unmatched because `_MIN_WORDSET_SUBSET_WORDS = 3` excludes the 2-word post-filter key)
- Next candidate fix: change `_MIN_WORDSET_SUBSET_WORDS = 3` to `2` on the filtered list (or check the minimum on the pre-filter word count)

## Iteration 6 — 2026-05-31

### can_match — admin-oaths — Mr. period-after-title OCR artifact

**Root cause:**
The preprocess step's `Mr.` normalization was applied BEFORE extracting the inner name
from a role+name parenthetical. So `The Second Deputy Prime Minister (Foreign Affairs)

the full string and had no effect → `strip_title` couldn't strip `Mr.` (period).

so it applies to the extracted inner name.

## Iteration 1 — 2026-05-31

### can_match — all types — constituency suffix in speaker string

**Affected Speech IDs (pilot):** ~39 (constituency-suffix pattern)

**Speaker string (failing):**
`Dr Tan Cheng Bock (Ayer Rajah)`, `Mr J. F. Conceicao (Katong)`, `Dr Dixie Tan (Ulu Pandan)`,
`Mr Teo Ser Luck (for the Minister for Community Development, Youth and Sports)`,
`Inche Sha'ari Bin Tadin (for the Minister for Culture)`

**Speaker string (passing, same report_type):**
`Mr Christopher de Souza`, `Mr Khaw Boon Wan`, `Dr Goh Keng Swee`

**Expected Mp.name:**
`Tan Cheng Bock`, `J.F. Conceicao` (inverted), `Dixie Tan` (or `Tan Dixie`), etc.

**Root cause:**
`_populate_speech_mp_ids` passes the raw `Speech.speaker` string (after rstrip(':')) directly
to `strip_title` and then `resolve_canonical_name`. When the speaker string carries a trailing
constituency or role parenthetical (`(Ayer Rajah)`, `(Nominated Member)`, `(for the Minister...)`),
the cascade cannot match the name because the lookup keys don't include the parenthetical.

**Proposed fix:**
Pre-processing step before `strip_title`: strip the trailing parenthetical from the raw speaker
string UNLESS its content starts with a title prefix (`Mr`, `Mrs`, `Dr`, etc.), which signals
a role+name pattern (`The Minister (Mr Name)`) that should be handled separately.

**Backward-compatibility:**
All 24 currently-passing pilot speeches have plain names with no parenthetical — the strip is
a no-op for them. Confirmed by simulation: 0 regressions in pilot + regression set.

**Outcome:** KEPT
- Pilot: 24/160 → 50/160 (15.0% → 31.2%), +26 newly matched
- Held-out: 22/93 → 34/93, +12 flipped
- Regression: 30/30 → 30/30, 0 new failures

`The Chairman`, `The Chief Minister` — no name present, unresolvable without role→MP mapping.
These are permanently unresolvable. Should be excluded from denominator if they are structural roles (not individual MPs). To be confirmed.
