# Data loss register

Every step that changes or drops source content between the raw API responses and any derived table, with its cost and the reason for it. Since 17 October 2026 this is a project requirement (`CLAUDE.md`, "Data loss register"): it covers attendance, persons, memberships, sittings, report titles and the hand overrides in `data/`, as well as markdown and speech rows. Written 15 October 2026, updated 16 October 2026 for write #3 and for the rehearsal of write #4, and 17 October 2026 for write #6 and the rows outside speech text, 17 October 2026 for write #7, 18 October 2026 for writes #8 and #9 and 19 October 2026 for the Parliament 15 backfill. Update a row in the same change that moves its figure.

## Principle

The raw API responses are stored exactly as received and are never rewritten: `HansardWebsiteResponse.content`, `Report.content` and the raw sitting table. Everything else is derived and can be rebuilt from them: markdown, speech rows, attendance. A transformation in this register therefore loses nothing for good. It loses it from the derived layer, and the parser can bring it back from the raw HTML.

Two things are not recoverable from the raw layer alone, and each says so below:
- Row ids. A write that deletes a speech row removes its id. The previous rows live in the `pg_dump` taken before each loop write. Those dumps sit outside git.
- Two fields the newer system serves are never stored. See "Exceptions to raw first".

## How to read the register

- **Cost** is the count the records give. "Not measured" means no file I read holds a count. The loop's counts come from dry runs and from the replica; where a figure is an estimate, the cell says so.
- **Reversible** is "yes" when re-running the parser on the raw HTML regains the content. A write that replaced stored rows is also undone by restoring the dump taken before it.
- **Stored rows** says whether the change reached the database. The combined write of 15 October 2026 (12:21), write #2 (15:46), write #3 (16 October, 16:03), write #4 (17 October, 07:48) and write #5 (17 October, 09:29) are in the stored rows. Write #4 is the three parser fixes of cycle 4 and the release of 42 held reports. Write #5 is the w5 parser patches 01a to 09 and the stage 8 links of patch 05.
- **Decided** gives the date and who decided, as the records show. "Project" means a commit or doc with no recorded user decision.

## Limits of the record

- Column numbers ("Column: 293" markers) are removed from every report before the row exists: 153,919 markers in 24,630 reports. A researcher cannot cite a column from a stored row. Keeping them needs a column and a rebuild of those reports (decision memo 02, finding 8).
- `speech.id` and (report, ordinal) are not stable across writes. Write #2 deleted 24,402 rows, write #3 shifted about 600,000 ordinals, and write #4 deletes 443 rows, inserts 66 and updates 3,234 ordinals. Only `pg_dump` files outside git hold the old ids. A citation to a row id is valid for one database state only.
- The rebuild of 1,568 near-match stale reports rested on a sample of 30 read against the source, none of which showed a hand edit. A sample of 30 with no hits bounds the hand-edit rate at under 9.5% (95% confidence); it does not show the rate is zero. Write #3 shipped and the pre-write dump is outside git, so the check cannot be repeated.
- Stage 7 writes attendance once per sitting: `populate_attendances` skips every sitting that already has rows, so a later change to name cleaning reaches no stored sitting until its rows are deleted or a script rewrites them. This loses nothing; it is why the attendance rows above each need a targeted write.
- The ADR 0002 misprint rate is unmeasured: 5 "Mdm Speaker" rows are known. The Knesset and GermaParl figures quoted in `vision.md` are point estimates on other units, not like-for-like rates.

## Exceptions to raw first

Three places where the raw layer is not the response as received.

- A NUL byte in a fetched report body becomes U+FFFD, not a deletion (`services/hansard_website.py`). The row is described under "Reports and raw rows".
- The gateway strips NUL bytes from a sitting response before the schema is built, so the stored row is what the schema saw (`utils/text.py::strip_nul`, `STYLE.md` sweep ruling 14, commit `d557ce7`, 1 Jun 2026). Count: not measured.
- Newer-system reports store only `resultHTML.content`. The other `resultHTML` fields, such as `mpNames` and `footNote`, have no column and are not stored. Footnote text is absent from the record for those reports; the footnote markers stay in the HTML ([ADR 0003](adr/0003-newer-system-raw-mapping.md)). Count: not measured.

## A metric change, not a data change

The text-share denominator changed on 15 October 2026. It counted the `Title:` and `MPs Speaking:` header fields as body text the parser dropped. They were 1.72M of 188.1M characters in Parliaments 0 to 11. Commit `7ba038f`, approved by the user, leaves them out. On the same stored rows, text share moves from 96.59% to 97.48%. F1 then lowered it by 0.07 points, because 135,406 characters of metadata had counted as linked speech. Text dropped inside reports that have rows fell from 1.22% to 0.41%. No stored text changed for this row. The figures before and after it are not comparable without the note.

The preamble ruling of 15 October 2026 moves 505,925 characters from dropped to rows with no speaker. A second change (commit `efa477d`) leaves the `(proc text)` tag out of the body character count in `scripts/attribution_text_share.py`, because it is markup: about 221,000 (22 per tag, 10,060 tags) characters.
