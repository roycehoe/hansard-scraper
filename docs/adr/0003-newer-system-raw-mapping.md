# 0003. Raw-first exceptions for the newer system

The raw tables store each API response as received, so a re-parse can start from the source. SPRS serves sittings from 10 September 2012 through a newer system whose responses do not fit the raw columns one to one, and the decision not to add tables or columns means some fields have no home. This record lists each exception, what is lost and where the data can be found instead.

1. Topic text. The newer system returns the report HTML as `resultHTML.content`; the older system returned it as `htmlContent`. Both are stored in `hansardwebsiteresponse.content`, the one text column, so a reader never needs to know which system served a row. The other `resultHTML` fields, such as `mpNames` and `footNote`, are not stored, because no column exists for them. Footnote text is therefore absent from the record for newer-system reports; the footnote markers stay in the HTML.
2. Assent to Bills Passed. Newer-system atbp reports return `resultHTML` as null, so their `content` stays null and they have no speech rows. Their bill list arrives as `resultData.atbpList`, the same data the sitting response gives as `a2bList`, which is stored in `sitting.a2b`.
3. Sitting lists. The nested sitting response carries `takesSectionVOList`, `annexureList`, `vernacularList` and `a2bList`. The raw table `hansardsittingdateresponse` has no column for them, so they are stored only on `sitting`, as JSON text in `sections`, `annexures`, `vernaculars` and `a2b`. An empty list is stored as `[]` and a missing key as null, so a reader can tell "nothing that day" from "never fetched". `attendanceList` and `ptbaList` are stored on both tables as JSON text, as before.
4. Attendance location. The API's `locationName` on an attendance entry marks where a member sat during a hybrid sitting and is set on 382 of 38,584 entries. `attendance.location_name` keeps the meaning it has in every pre-2012 row, the constituency parsed from the name, and the API value stays inside `attendance_list`.
5. Full-sitting HTML. The newer system serves no `htmlFullContent`, so `html_full_content` and `sitting.markdown_content` stay null from 10 September 2012 and attendance is built from the structured list instead.
