# 0011. Name resolution in utils

Status: accepted, 22 October 2026. Royce chose this layout during the grill for style sweep 2 (`plans/style-sweep-2-brief.md`, decision 5). It took effect in the style sweep 2 commits 37a1069 to 1e5969c.

Context. Stages 7 and 8 both turn a printed name into a `Speaker` name. Stage 7 does it while it builds attendance rows (`services/attendance.py`). Stage 8 does it while it sets `speaker_id` on speech and attendance rows (`populate/speaker_links.py`). STYLE.md says pure logic does not live in `populate/`, and seven scripts were importing the stage 8 resolver from there. Moving the resolver into `services/` would make it import `services/attendance.py` and the role-context service. STYLE.md grades an import between two `services/` peers `blocking`, and says the shared code comes from `utils/`.

Decision. Name resolution moves to `utils/speaker_resolution.py`, next to `utils/speaker_resolution_constants.py`. That is the name tables, `SpeakerLookups`, `resolve_canonical_name` and the key helpers they share. `build_speaker_lookups` and its `_build_*_lookup` builders stay in `services/attendance.py`, because they read `Speaker` rows and `utils/` imports nothing from `database/`. They build the `SpeakerLookups` that `utils/` defines. The resolver never builds lookups (only the stage entry points do), so it needs nothing from `services/attendance.py`. `VOLUME_TO_PARLIAMENT` and `infer_parliament` move to `utils/parliament_numbers.py`, since the resolver and attendance parsing both read them. The role-context service became `services/speaker_link.py` and took the stage 8 resolver. `services/attendance.py` keeps the attendance list parsing, and both services import name resolution from `utils/`.

Why. Two alternatives were rejected. The first would have recorded the two `services/` imports as a licensed exception, which writes a hole into a `blocking` rule on the day a sweep is meant to remove its counter-sites. The second would have left the resolver in `populate/` and let scripts import it, which keeps the layering this sweep exists to fix. The cost of the choice is that every importer of `resolve_canonical_name`, `SpeakerLookups`, `VOLUME_TO_PARLIAMENT` and `infer_parliament` changes in one commit, and `utils/` now holds Hansard-specific logic. The 24 callers of `build_speaker_lookups` keep their import and their call. STYLE.md allows `utils/` to hold a helper two `services/` peers share, and name resolution is that helper. The move changes no resolved name. The proof is a run over the full corpus on `hansard_replica` that gives identical speaker ids before and after.
