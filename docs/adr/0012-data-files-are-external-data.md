# 0012. Data files are external data

Status: accepted, 23 October 2026. Royce made this call after style sweep 2, which left two scripts reading `data/` files as raw dicts. It took effect in the style follow-up 1 commits d46f6d1 to 12fc21d (`plans/style-followups-1.md`), with this record.

Context. `data/` holds ten hand-edited JSON files: overrides, exclusions, colonial members, party histories and person decisions. STYLE.md's blocking rule "Parse at the boundary before reading a field" covers anything from outside the process, and these files come from outside it. Six of them were read through schemas in `utils/data_files.py`. `populate/persons.py` built `person_decisions.json` into a dataclass by hand and dropped its `source` key. `scripts/load_heads_of_state.py` and `scripts/load_colonial_la_speakers.py` read their files raw. `scripts/load_party_affiliations.py` and `scripts/clean_attendance.py` validated theirs but each opened its own path, and about ten tests opened the files themselves. Pydantic ignores keys a schema does not declare, so a mistyped key in a hand-edited file vanished without an error.

Decision. Every `data/` file is read once, through its own schema, by one loader. Each file has one schema in `schemas/`, and a file whose top level is a list gets a `RootModel` that names the whole file. A data-file schema sets `extra="forbid"` and `frozen=True`. API schemas keep the default that ignores unknown keys. A field is required unless some records leave it out. A rule about the whole file, such as unique ids, is a `model_validator` on the root model. `utils/data_files.py` holds one `get_<file>()` per file, built on `Schema.model_validate_json(path.read_bytes())`. It is the only module that opens `data/`, and populate, scripts and tests all call it. One wrapper there turns a `ValidationError` into `HansardDataFileError`, naming the file. STYLE.md licenses `utils/data_files.py`'s file reads as the second named impurity, after `database/init.py`.

Why. A file people edit by hand fails in ways an API body does not: a key spelt wrong, a record missing a field, a duplicate. Forbidding unknown keys turns each of these into a load error that names the file and the record's index. Ignoring them would store a default and say nothing. One loader means a test checks exactly what the pipeline reads. A `RootModel` keeps the `Schema.model_validate` pattern STYLE.md already names, where a `TypeAdapter` would be a second idiom for the same job. The cost is behaviour: a bad record now stops the stage at load, where before it failed later or not at all. Every file must pass its strict schema in the batch's first commit, before any reader moves to it.
