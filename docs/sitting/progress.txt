## Setup — Artifact catalogue

Five artifact categories identified across 20 pilot documents.

A. **broken-table-metadata** — `---|---` lines throughout document
   Cause: html2text renders every 2-column <table> header as "---|---" separator.
   Appears at: (1) metadata table top of doc, (2) speaker-signature tables (end of
   each day's agenda), (3) part/volume info table (modern era), (4) bills/dates tables.
   Affects: 20/20 pilot docs (universal across all eras and volume strata).

B. **broken-italic-lines** — lone `_` line (italic marker orphan)
   Cause: <BR> or line-break inside <i> tag; html2text renders the closing `_` on a
   new line. Appears in: (1) date header area, (2) sitting-suspension notices,
   (3) bill explanations, (4) adjournment line.
   Affects: 5/20 pilot docs (vol 81–87 modern era only).

C. **appendix-links** — markdown links to PDF/GIF appendix files
   Cause: <a href="/search/..."> elements in document tail and inline.
   Note: deferred in previous loop as a product decision. Still unresolved.
   Affects: 10/20 pilot docs.

D. **missing-space-before-time** — space missing before time in meeting header
   Cause: Source data quality — space absent in raw HTML between "at" and time digits.
   Unfixable without source correction or NLP. Affects: 3/20 pilot docs (vol 81–87).

E. **adj-split-false-positive** — heuristic mis-fires on vol 87 italic adjournment
   Cause: vol 87 adjournment uses italic spans: `_Adjourned accordingly at_`
   `_Five Minutes to Seven o'clock pm._` — text is on one line but ends with `._`
   not `.`, so heuristic (endswith('.')) fires incorrectly. Not a true split.
   Affects: 3/20 pilot docs (vol 87 only). Not a real artifact.

## Iteration 1 — 2026-05-31

### Artifact: broken-table-metadata

**Affected IDs:**
All 20 pilot docs. Universal across vol 31–87.

**HTML snippet (exhibiting artifact):**
```html
<tr><td>Parliament No:</td><td>10</td></tr>
<tr><td>Session No:</td><td>2</td></tr>
```
Also speaker-signature tables:
```html
<tr><td>YEOH GHIM SENG</td></tr>
<tr><td><i>Speaker,</i></td></tr>
```

**Markdown output (before fix):**
```
| Parliament No:| 10
---|---
Session No:| 2
```
And speaker signature:
```
| YEOH GHIM SENG
---|---
| _Speaker,_
```

**Root cause:**
html2text renders 2-column HTML tables as:
- Header row: `| col1| col2`
- Separator:  `---|---`
- Data rows:  `col1| col2`  (subsequent rows lose the leading `|`)
This `---|---` line appears 1–5 times per document from multiple table types.
The separator itself is harmless to strip; the surrounding content (pipe-prefixed
metadata lines) is noise but not the highest-impact item in this iteration.

**Proposed fix:**
`_remove_sitting_table_separators`: strip lines whose stripped value is exactly `---|---`.
Backward-safe: this string does not appear as intentional Hansard content.
`get_cleaned_report_markdown` is untouched.

**Outcome:**
KEPT. broken-table-metadata: 20/20 → 0/20 (pilot), 0/12 (held-out), 0/20 (regression).
No new artifacts introduced.


## Iteration 2 — 2026-05-31

### Artifact: broken-italic-lines

**Affected IDs:**
52, 55, 56, 57, 60 (pilot — all vol 81–87); 54, 50, 61 (held-out); 59, 58 (regression vol 87).

**HTML snippet (exhibiting artifact):**
```html
<i>Tuesday, 7th March, 2006<BR></i>
```
And mid-document:
```html
<i>Sitting accordingly suspended at<BR>2.51 pm until 3.10 pm.</i>
```

**Markdown output (before fix):**
```
_Tuesday, 7th March, 2006
_
```
Or:
```
_Sitting accordingly suspended at
2.51 pm until 3.10 pm.
_
```

**Root cause:**
`<BR>` inside `<i>` tag causes html2text to place the closing `_` italic marker on a
new line. The orphan `_` appears in the header area (date), mid-doc suspension notices,
bill explanations, and adjournment lines in vol 81–87 documents.

**Proposed fix:**
`_remove_sitting_orphan_italic_markers`: strip lines whose stripped value is exactly `_`.
Backward-safe: a lone `_` does not appear as intentional Hansard content (single
underscore is not a valid standalone markdown element or Hansard phrase).

**Outcome:**
KEPT. broken-italic-lines: 5/20 → 0/20 (pilot), 0/12 (held-out), 0/20 (regression).
No regressions.


## Iteration 3 — 2026-05-31

### Artifact: extended empty-bold (standalone ****+ and ****-prefixed content)

**Affected IDs:**
Standalone ****+: IDs 55, 56, 57 (pilot vol 87); IDs 50, 54, 61 (held-out vol 87); IDs 58, 59 (regression vol 87).
****-prefixed content: IDs 52, 55 (pilot vol 81-87); ID 6 (regression vol 31).

**Markdown output (before fix):**
```
_Adjourned accordingly at_ _Two Minutes to Seven o'clock pm._
********
********
**APPENDICES**
```
And:
```
****Debate in Committee of Supply resumed.
****FINANCIAL****
```

**Root cause:**
The existing `_remove_sitting_empty_bold` only stripped exactly `****` (4 stars). Two sub-patterns escaped:
1. `********` (8 stars): two adjacent `<b></b>` at section boundaries in vol 81-87.
2. `****Content` or `Content****`: single `<b></b>` adjacent to real content, so html2text
   concatenates the empty-bold markers onto the content line rather than producing a
   standalone empty line. Also `****FINANCIAL****` from `<b></b>FINANCIAL<b></b>`.

**Proposed fix:**
Extend `_remove_sitting_empty_bold`:
- Drop lines that are entirely asterisks (regex `\*+\s*`)
- Strip leading `****` and trailing `****` from content lines

**Outcome:**
KEPT. standalone ****+: 3/20 → 0/20 (pilot), 0/12 (held-out), 0/20 (regression).
****-prefixed: 2/20 → 0/20 (pilot), 0/12 (held-out), 0/20 (regression).
FINANCIAL line correctly rendered as plain `FINANCIAL`. No regressions.

Two new issues found during second sample inspection:

### Iteration 4 — Bug fix: multi-group leading **** strip

**Artifact:** `****6.**Speaker** asked...` (question-numbered lines in vol 87)
**Root cause:** html2text produces `********6.**...` (two empty bolds = 8 stars) before the
question number. `_remove_sitting_empty_bold` used `re.sub(r'^\*{4}', ...)` which only
strips the FIRST group of 4 stars, leaving a residual `****` prefix.
**Fix:** Changed to `re.sub(r'^(\*{4})+', '', line)` and `re.sub(r'(\*{4})+$', '', line)`
to strip ALL consecutive groups of empty-bold markers.
**Outcome:** KEPT. ****-prefixed content: 1/20 → 0/20 (pilot), 0/12 (held-out), 0/20 (regression).

### Iteration 5 — Adjournment merge stop at `._`

**Artifact:** vol 87 italic adjournment: `_Adjourned accordingly at_ _Time_` merged with
following section `WRITTEN ANSWERS TO QUESTIONS...` onto one line.
**Root cause:** Adjournment in vol 81–87 uses multiple italic spans. The merged line ends
with `._` (period + italic close `_`), which `endswith(".")` doesn't catch — so the merge
continued into the next section.
**Fix:** Added `not line.rstrip().endswith("._")` as a second stop condition in
`_merge_sitting_adjournment_lines`.
**Outcome:** KEPT. adj-split (true): 4/20 → 0/20 (pilot), 1/12 (held-out — ID=47 vol=31,
source data has no final period), 0/20 (regression). Not a rendering artifact.

## Iteration 6 — 2026-05-31

### Artifact: 1-col-table-separator

**Affected IDs (pilot):**
64, 65, 69, 70, 74, 75, 79, 80, 84, 85 (new vols 39,44,51,58,66) +
51, 50, 5, 7, 11, 18, 9, 20 (old vols 39,50,57,66)

**HTML snippet (exhibiting artifact):**
```html
<table width="100%" border="0">
  <tr><td><b>PART V OF FIRST SESSION</b></td></tr>
</table>
```

**Markdown output (before fix):**
```
**PART V OF FIRST SESSION**
---
```
The `---  ` immediately follows the bold line. CommonMark parsers may treat this as a
Setext h2 heading underline, silently promoting the preceding line to a heading.

**Root cause:**
html2text renders 1-column `<table>` rows the same way as 2-column tables but the
separator is `---  ` (3 dashes + trailing spaces) instead of `---|---`.
`_remove_sitting_table_separators` only matched `---|---`, missing this variant.

**Proposed fix:**
Extend `_remove_sitting_table_separators` to also strip lines matching `re.fullmatch(r'-{3}\s*', line)`.
Safe: html2text renders `<hr>` as `* * *` — so `---` lines in these docs are always table artefacts.

**Outcome:**
KEPT. 1-col-table-separator: 18/40 → 0/40 (pilot), 0/24 (held-out), 0/38 (regression).
No new artifacts introduced. All prior fixes still hold.
